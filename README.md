# Media Content Recommendation Engine

Rank a media catalog per user — the same problem class as content discovery and
personalization on a streaming platform: popularity baseline → collaborative
filtering (item-item, NMF) → content-based (TF-IDF) → hybrid ranker with a
cold-start fallback, evaluated offline with Precision@10 / Recall@10.

## Data (synthetic, seed-42)

Generated by `data/generate_datasets.py`. Documented as synthetic — no claim of
real user behaviour.

| File | Rows | Contents |
|---|---|---|
| `data/users.csv` | 5,000 | user_id, age_band, region, device |
| `data/content.csv` | 1,500 | content_id, genre, tags, language, duration_min |
| `data/interactions.csv` | 175,540 | user_id, content_id, event, event_ts (2026-07-01 → 2026-09-30) |

Events: impression → play → completion → like.

| Funnel step | Rate |
|---|---|
| play \| impression | 40.3% |
| completion \| play | 41.2% |
| like \| completion | 17.9% |

Play/completion probability rises with each user's genre affinity, so the data
carries real personalization signal. User–item density is 1.43% (98.6% sparse);
361 users (7.2%) have fewer than 5 plays — the cold-start population.

## Method

- **Split:** temporal 80/20 train/test on `event_ts` — no future behaviour leaks
  into training. Relevance = completion or like.
- **Features:** implicit-feedback weights (impression=1, play=2, completion=3,
  like=5); TF-IDF over genre + tags + language.
- **Models:** popularity ranker, item-item cosine, NMF (20 latent factors),
  content-based user profiles, hybrid (0.5 CF + 0.3 content + 0.2 popularity,
  min-max normalized). Users with no train history fall back to popularity.
- **Evaluation:** Precision@10 / Recall@10 on 300 sampled test users; items
  already seen in train are excluded from recommendations.

## Results

| Model | P@10 | R@10 |
|---|---|---|
| popularity | 0.0080 | 0.0678 |
| nmf | 0.0080 | 0.0611 |
| item-item | 0.0060 | 0.0444 |
| hybrid | 0.0060 | 0.0467 |
| content-based | 0.0020 | 0.0144 |

**Honest finding:** on this sparse synthetic catalog the hybrid does not beat
plain popularity — personalization signal exists but is drowned out by
sparsity at this scale. That is a real result, not a failed experiment: it is
why production systems blend popularity priors and invest in denser feedback
loops. Full per-model numbers in `data/model_leaderboard.csv`.

## Run it

```bash
pip install -r requirements.txt

# regenerate the data (optional)
python data/generate_datasets.py

# rebuild + execute the notebook
python build_notebook.py
jupyter nbconvert --to notebook --execute --inplace \
  notebooks/recommendation_engine.ipynb

# dashboard
streamlit run dashboard/app.py
```

The three SQL queries in `sql/ranking_metrics.sql` run on MySQL/MariaDB 10.2+
(window functions) against the same three tables.
